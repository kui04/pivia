# Frontend

Component conventions live in [components.md](components.md). Frontend code lives in `packages/web`.

## Environment

- Pin `typescript` to `~6.0.3` because `typescript-eslint` 8.x requires `<6.1`. Do not upgrade to TypeScript 7 without replacing type-aware linting.
- Pin `playwright` in `packages/web/package.json` to the exact `playwright-driver` version from nixpkgs so Chromium revisions match inside `devenv shell`.

## Module Entry Points

- Every component folder owns an `index.ts` barrel: the design system under `components/<Name>/`, the workspace components under `pages/Workspace/components/<Name>/`, the composer components under `pages/Workspace/components/Composer/components/<Name>/`, and the transcript components under `pages/Workspace/components/Transcript/components/<Name>/`. Import the folder, not its implementation file: `@components/Icon`, `../IconButton`, `@components/Toast`. The folder barrel is the only place that joins the folder name to its implementation file.
- The public app-wide barrels are `@components`, `@/hooks`, `@/lib`, and `@/stores`. `@components` re-exports the design system; `@components/<Name>` reaches one component folder. `@/stores` is the composition root only; import domain factories and types from `@/stores/auth`, `@/stores/session`, or `@/stores/workspace`.
- Feature modules follow the same rule. Import the transcript view and its queue helpers from `pages/Workspace/components/Transcript`, workspace shell components from `pages/Workspace/components`, and route pages from their folder barrels such as `@/pages/Workspace`. Do not add a `pages/index.ts` aggregate; each route stays explicit in `router.tsx`.
- Subsystem entry points are `@/lib/cache`, `@/lib/sync`, and `@/lib/transport`. Import their public types and functions from the barrel instead of a file inside the subsystem.
- Keep a deep import only when a barrel would load browser-only assets into a Node unit test. `lib/toast.ts` imports `Toast/useToast`, `stores/session/tool-details.ts` imports `CodeBlock/highlight`, and Workspace layout utilities import `SplitPane/tree` and `SplitPane/dnd` for this reason. Move a generic helper to `lib` before widening a barrel, and keep component-coupled helpers inside their component folder.

## Styles

- `packages/web/src/styles/token.css` holds the design tokens (VS Code Modern colors mapped to Material 3 roles, M3 Expressive type/shape scales, spacing, elevation, and motion). Use tokens instead of raw values; ask before adding tokens or using raw values.
- `--color-outline-control` provides the 3:1 boundary for interactive controls (`Input`, `Select`, `Checkbox`, secondary `Button`); `--color-outline` stays the decorative separator.
- `--color-tertiary` is the single purple accent for skill invocation headers, extension message headers, non-failed `!!` command borders, the sidebar `needs-input` dot, and the contrast-safe >70% context warning in `SessionStatusBar`. Keep it out of error roles.
- Load order in `packages/web/src/main.tsx` (and mirrored in `packages/web/.storybook/preview.ts`) is `token.css`, `reset.css`, `global.css`. `reset.css` is a trimmed Tailwind v4 Preflight; `global.css` holds document-level defaults (`font-sans`, `--type-body-*`, `font-size-adjust: from-font`, `font-synthesis: none`).
- Colors use `light-dark()` with `color-scheme`. Set `data-theme="light"` or `data-theme="dark"` on `<html>` to override the system theme.
- Fonts (`Google Sans`, `Newsreader`, and `JetBrains Mono` via `@fontsource-variable/*`, Latin subset only) live in `packages/web/src/styles/fonts/*.css` and load lazily through `packages/web/src/lib/fonts.ts` (`scheduleDefaultFonts`, `ensureFontRole`, `applyFontPreset`) and `useFontRole`: `sans` loads during browser idle time, while `mono` and `serif` load on demand when matching surfaces mount. Because `global.css` sets `font-synthesis: none`, every weight and style must be covered by the active variable face.

### CSS Nesting

CSS Modules use native nesting (no preprocessor). Follow these rules:

- **Nest by DOM containment**: Nest `.child` under `.parent` only when TSX or story markup proves containment; never nest siblings or portaled elements. Use `&:` and `&[...]` for states on the same element (only use `&.otherClass` to match an existing compound selector's specificity). Nest `@media`, `@supports`, and `@container` inside a block only when all inner rules share that block. Keep declaration order so nesting never breaks the cascade.
- **Protect class specificity**: Keep classes passed to child components via `className` (`Button`, `Input`, `IconButton`, `ScrollArea`, ...) and co-located modifier presets (such as size or radius classes) at the top level so they keep `(0,1,0)` specificity. For a public `className` accepted by a component (`Dialog`, `Menu`, ...), wrap ancestors with `:where()` so nesting adds zero specificity (`.viewport { :where(.popup) { ... } }`).
- **Header tree sketch**: Start every `*.module.css` file with an ASCII tree (`├─`, `└─`, `│`) of its authored CSS nesting (use one line for single-class modules), and update it in the same change when nesting changes. See [ScrollArea.module.css](../packages/web/src/components/ScrollArea/ScrollArea.module.css) for the canonical format.

## Viewport and Keyboard

- `packages/web/src/main.tsx` listens to `visualViewport` and writes `--vv-height`, `--vv-offset-top`, `--kb-inset`, and `data-keyboard-open="true"` on `<html>`.
- Pages use `--kb-inset` for bottom actions and scroll clearance. Never combine `--kb-inset` with `--vv-height` on the same layout, or the keyboard inset applies twice.

## Storybook and Testing

- Stories live beside components as `*.stories.tsx`. `packages/web/.storybook/main.ts` enables `@storybook/addon-docs`, `@storybook/addon-a11y` (`test: "error"` in `preview.ts`, opt-out via `parameters: { a11y: { test: "todo" } }`), and `@storybook/addon-vitest`.
- Story-only helpers live in `packages/web/src/storybook/`: `requireElement` and `requireViewport` throw with the missing node's name, `mockClipboardSuccess` and `mockClipboardFailure` stub the clipboard, `waitForTheme` and `waitForDarkTheme` wait for a theme decorator, `ids.ts` parses story ids and sync literals, `fixtures.ts` builds shared story rows and images, `socket.ts` provides the in-memory `StorySocket`, `frames.tsx` exports `TranscriptFrame` and `StoryRow`, `DarkTheme` and `LightTheme` pin the document theme for a story, and `frames.module.css` provides the shared story layouts.
- Node unit-test helpers live in `packages/web/src/test/`: `ids.ts` parses ids and sync literals, `fixtures.ts` builds session rows and snapshots, `fake-socket.ts` provides `FakeWebSocket` (call `FakeWebSocket.reset()` in `beforeEach`), and `local-storage.ts` installs an in-memory `localStorage` (call it from module scope or `beforeEach`, never from `vi.hoisted`, which runs before the import). These modules must stay free of CSS, React components, and browser-only imports.
- `packages/web/vitest.config.ts` defines the `unit` (`*.test.ts` in Node) and `storybook` (Chromium via Playwright) projects. Run Storybook browser tests inside `devenv shell` and stop the Storybook dev server first so workers do not contend for memory.

## Routing and Hooks

- `packages/web/src/router.tsx` creates one `createBrowserRouter` instance at module load (never in React state); the Node server falls back non-API paths to `index.html`. React Router 8 imports `RouterProvider` from `react-router/dom` and hooks/components from `react-router`.
- `AppLayout` (`packages/web/src/pages/AppLayout/`) is the root route owning shared chrome and the single-host auth gate (`checking` / `unauthenticated` / `authenticated`). The root `errorElement` renders `RouteError` outside `AppLayout`.
- `/workspace` (`WorkspaceLayout`) owns the workspace shell (sidebar/drawer, settings, rename/new-session dialogs, catalog sync, resizable/dockable split-pane layout via `SplitWorkspace` over `@components`'s `SplitPane` + `SessionPane`, and multi-session background keep-alive via `sessionPool`) while syncing the focused pane with `:sessionId`. Standalone `WorkspacePage` binds an injected `sessionStore` for isolated stories and tests.
- Reusable component-free hooks live in `packages/web/src/hooks/<name>.ts` and are re-exported from `packages/web/src/hooks/index.ts`; import them via `@/hooks` (`useDropTarget` provides flicker-free HTML5 drop-zone tracking for split docking). Component-scoped hooks stay in `components/<Name>/`; page-scoped hooks stay in `pages/<Name>/`.

## Formatting

- Component-free display and formatting helpers live in `packages/web/src/lib/` and are re-exported from `packages/web/src/lib/index.ts`; import them via `@/lib`. `Formatter` groups the duration, byte size, USD cost, token count and relative age formatters, `Fuzzy` exposes pi-tui-compatible fuzzy matching and filtering, and `Clipboard` owns clipboard text writes and image file reads. They take plain values and return plain values or strings so components and stores share one output. Domain-specific message composition (for example a compaction note or a truncation warning) stays with the store that owns the data.

## State, Cache, and Transport

- Store factories (`createAuthStore`, `createSessionStore`, `createSessionPool`, `createWorkspaceStore`) live in `packages/web/src/stores/<name>/` with no cross-store imports or module-load side effects. Each domain exposes an `index.ts` barrel (`@/stores/auth`, `@/stores/session`, `@/stores/workspace`). `packages/web/src/stores/index.ts` (`createAppStores`) wires the singletons (`useAuthStore`, `sessionPool`, `useWorkspaceStore`) and is the only app-wide store entry point.
- `packages/web/src/lib/cache/` owns `IndexedDbAppCache` (`appCache`, backed by `IndexedDbCoordinator` with in-memory fallback). Stores accept narrow interfaces (`SessionCache`, `WorkspaceCatalogCache`, `ClearableCache`), and sign-out, `401` responses, or `markUnauthorized()` (including `useWorkspaceSync`'s `authProbe`) trigger `clearAll()`.
- HTTP/WebSocket clients stay in `packages/web/src/lib/transport/`, consuming `HTTP_ENDPOINTS`, `WS_ENDPOINTS`, and wire decoders from `@pivia/protocol` (`websocket.ts` provides shared WebSocket helpers). Import them through `@/lib/transport`. Real-time streams use `packages/web/src/lib/sync/` (see [versioned_incremental_sync.md](versioned_incremental_sync.md)).

## Workspace Sync and Session View

- **Catalog sync (`useWorkspaceSync`)**: Hydrates stale catalog rows from IndexedDB on mount, subscribes to `/ws/workspace` for `SyncFrame<"catalog", CatalogSnapshot, CatalogDelta>`, reconnects with backoff (and wakes on visibility change), probes `/api/auth/status` after repeated closes, and exposes single-flight manual refresh via `GET /api/sessions`. Keep cached rows visible under a status banner during `reconnecting` or `failed`; show skeleton rows during `syncing` with `focusableWhenDisabled` on the refresh button.
- **Session pool & split layout (`SessionPool`, `splitLayout`, `useWorkspaceSession`)**: `WorkspaceLayout` manages a binary split-pane tree (`splitLayout.ts`, persisted in `localStorage`) bounded by configurable minimum pane dimensions (`minPaneWidthPx`, `minPaneHeightPx`) and keeps every visible pane plus an LRU budget of idle background sessions (`DEFAULT_MAX_BACKGROUND_SESSIONS = 8`, skipping streaming/compacting/pending-UI sessions during eviction) attached concurrently via `createSessionPool`. Sidebar rows expose `Split right`, `Split down`, and `Close session`, while each pane overflow menu owns `Detach session` (clearing only that pane slot) and `Close pane`. Standalone `WorkspacePage` uses `useWorkspaceSession` to bind an injected `sessionStore` for isolated stories and tests.
- **Extension prompts (`ExtensionUi`, `SessionPool.needsInputIds`)**: Protocol codecs (`parseSessionSnapshot`, `parseSessionDelta`) decode `pendingUiRequests` at the wire boundary, and `SessionPane` renders the oldest request through `ExtensionUiPrompt`, which counts down the request's own `timeout` from the moment it reaches the queue head (the server still owns the timer and closes the dialog with `ui_resolved`). While a request is pending the composer is blocked and its primary action becomes the prompt button with a pending-count badge; minimizing hides the modal but keeps the request pending, and the button reopens it. Only the focused pane opens the modal, so a split layout never stacks two modal backdrops. `SessionPool` publishes `needsInputIds` for the sidebar dot, and its keep-alive rule protects a pending session from background eviction. `notify` requests and `extension_error` deltas collect in `SessionState.notices`, which `SessionPane` drains into the shared toast stack; `set_editor_text` bumps `editorTextRequest.sequence`, and `Composer` applies each sequence once and acknowledges it. The session snapshot also carries `uiState`: status lines join above the composer, widgets render on their requested side, and only the focused pane writes `document.title` from `setTitle`.
- **Telemetry (`SessionStatusBar`, `SessionStatsDialog`, `summarizeSessionStats`)**: the strip below the composer derives token/cost totals and the cache hit rate from the synced entries (skipping the session header, matching the SDK's `getSessionStats()`), and reads `contextUsage`, `routedModel`, and `model.contextWindow` from the snapshot. Context usage above 70% uses the tertiary accent and above 90% the error color, both of which keep small-text contrast; the session menu opens the detailed stats dialog, which never shows the session file path.
- **Transcript projection invariants**: Components never walk the entry tree directly. `projectSessionTranscript` (`packages/web/src/stores/session/projection.ts`) resolves active branch, compaction boundary, and `context_edit` replacements; `buildTranscript` (`packages/web/src/stores/session/transcript.ts`) folds entries plus `liveAssistantMessage` into user, skill, bash (`!` / `!!`), extension (`custom_message` via `CollapsibleBlock` with `tone="accent"`), note, and turn items.
- **Transcript row identity**: A mounted pane builds rows through `createTranscriptRowBuilder` instead of calling `buildTranscript` per token. The builder plans once per projected entry list and rebuilds only the trailing turn, so every settled row keeps its item object and its `memo`ized component bails out of a streamed token. Pass the same projected array between calls; a new array rebuilds every row.
- **Transcript virtualization**: `Transcript` mounts its rows through virtua's `Virtualizer` inside the existing `ScrollArea`. Only rows near the viewport are in the DOM; a turn row the reader expanded is passed to `keepMounted` so its state and measured height survive scrolling away, and the trailing chrome (working indicator, activity notice, queue) stays mounted in `.column` outside the list. Each mounted row gets a `.row` wrapper that owns the inter-row gap and the first row's top inset, because the virtualizer measures the item element's content box: spacing on an item or on `.content` would fall outside the measured list; a transcript without rows mounts no list, so the chrome keeps that inset through `.column[data-empty]`. Off-screen rows are absent from the DOM, so browser find-in-page, sequential keyboard navigation and assistive technology only reach the mounted window: the row that unmounts under the focused element loses focus, and Tab skips the content between mounted rows. These are known limits of virtualizing rows, not defects to fix here. A footnote target stays reachable because references and definitions live in one row. A compaction that drops leading rows keeps a pinned reader at the bottom because the browser clamps the offset to the shorter extent, and holds a released reader's content in place through the virtualizer's `shift`; the row builder reports that case as `droppedLeadingEntries` for the one render that shrinks the list, and the compensation is exact for rows the reader had mounted and an estimate for rows that never were; when the drop moves the top inset to another row, the content below can shift by that inset.
- **Transcript initial bottom**: `useAutoScroll` enters a settling phase after it attaches a viewport with `initialBottom`: the hook follows every layout pass until the extent stops growing, because a virtualized list reports its rows one layout pass after the first commit. The phase closes when a layout pass reaches the bottom (the write precedes the commit that lifts the veil, so no frame paints a stale offset), after a quiet window that only starts once the list reported a measurement through `reportMeasured`, or when the reader scrolls up; a jump to the bottom during the phase keeps it alive. The view keeps `.column` hidden (`data-pending`) until then, so a cold open never paints the top of the transcript and then jumps. While hidden, the column is outside the accessibility tree, so an activity notice that appears in that window joins the tree only when the column appears; whether a screen reader then announces it depends on the reader. Streaming keeps following through the `pinned` state as before.
- **Transcript module boundary**: Pages import `projectSessionTranscript`, `createTranscriptRowBuilder`, and the transcript view-model types from `@/stores/session`; `buildTranscript` stays the one-shot fold for tests and callers without a mounted view. The transcript component entry is `pages/Workspace/components/Transcript/index.ts`, which exposes `Transcript`, `collectQueuedEntries`, and `QueuedEntry`. `tool-details.ts`, `transcript-meta.ts`, `readers.ts`, and `skill-block.ts` are internal collaborators; import them directly only in a colocated test that targets their boundary parsing.
- **Tool display split**: `transcript.ts` classifies each call (`toolKind`) and derives its argument summary; display labels and icons live with the view in `ToolCallBlock/toolDisplay.ts`, while the model carries only the raw `toolName`.
- **Timing exclusivity**: `TranscriptTiming` is a discriminated union (`static` final duration vs `since` start timestamp) so callers cannot add live elapsed time to a snapshot duration twice. Only the trailing turn of an active runtime may show an unmatched tool call as `running`; historical unmatched calls are `error` (interrupted).
- **Page state order**: `selectWorkspaceView` (`packages/web/src/pages/Workspace/workspaceView.ts`) resolves `loading` -> `terminalError` (or cached `transcript` when closed with rows) -> `syncError` (or cached `transcript` with a retry banner) -> `empty` -> `transcript`.

## Toasts

- `packages/web/src/lib/toast.ts` exports the single `toastManager`, `showError`, and `showWarning`. `main.tsx` mounts the single `ToastProvider` at top center; never mount a second provider.
